# MAX Архив

Расширение Chromium для локального сохранения переписки из [веб-версии MAX](https://web.max.ru/). Данные обрабатываются в браузере; серверов проекта нет.

## Установка

1. Скачайте или клонируйте этот каталог.
2. Откройте `chrome://extensions` (или `edge://extensions`), включите режим разработчика и выберите **Загрузить распакованное расширение**.
3. Укажите каталог `MaxExport`, откройте `https://web.max.ru/` и войдите в свой аккаунт.
4. Откройте чат и нажмите значок расширения. **Экспортировать открытый чат** запускает сохранение с настройками по умолчанию; **Настройки и выбор чатов** открывает отдельную страницу.

В расширенном режиме можно выбрать открытый чат, несколько чатов либо все найденные чаты текущей папки MAX. Есть форматы HTML + JSON, HTML, JSON, CSV и TXT; период, ссылки, реакции, адреса медиа, скачивание доступных вложений и предел сообщений. По умолчанию расширение скачивает отдельный ZIP для каждого чата; можно выбрать один общий ZIP. В каждом ZIP есть `report.json` с итогами, пропусками и версией расширения (`extensionVersion`). Поле `history` у чата содержит число попыток прокрутки, замен панели, общее `elapsedMs`, режим ожидания `pacing` и параметры последних 20 шагов без текста сообщений. В шагах записываются `waitMs`, `visibility` и состояние индикатора загрузки `loading`. При экспорте нескольких чатов отдельными архивами дополнительно скачивается `max-archive-summary.json`.

В режиме **Выбранные чаты** кнопки **Выбрать всё** и **Снять выбор** меняют отметки сразу во всём найденном списке. Число выбранных чатов видно перед запуском экспорта.

Ход работы показывает число обработанных чатов, состояние каждого чата и текущий этап: открытие чата, загрузка истории, получение адресов файлов, загрузка вложений, создание ZIP. Сначала расширение прокручивает историю до заданного максимума сообщений или её начала, собирая сообщения из сменяющихся участков DOM. На этом этапе кнопки файлов не нажимаются. Затем отдельным проходом оно находит файлы выбранных сообщений, получает адреса, загружает вложения и создаёт архив. Для загрузки истории точный процент неизвестен; счётчик показывает найденные сообщения. При получении адресов показываются обработанные вложения X из Y, имя текущего файла и секунды ожидания; счётчик обновляется и после обработки. При загрузке вложений также отображается число обработанных файлов. Повторный запуск сбрасывает индикаторы предыдущего экспорта. Кнопка **Остановить** прерывает ожидание адреса и текущую загрузку файла, затем останавливает последующие чаты.

## Просмотр HTML-архива

Распакуйте ZIP, сохранив `messages.html` и каталог `media` рядом. Скачанные фотографии (в том числе GIF и доступные стикеры-изображения) показываются внутри переписки; нажатие открывает файл. Видео и аудио/голосовые записи с доступным файлом получают встроенные плееры. Документы остаются ссылками на локальные файлы. Тип определяется по MIME-типу ответа, типу вложения и расширению. Воспроизведение зависит от кодеков браузера; рядом с каждым плеером остаётся ссылка на файл. Автовоспроизведения нет.

Включите **Скачать вложения**, чтобы получить локальные превью. Нескачанные внешние изображения не загружаются автоматически при открытии HTML: остаются ссылки. Вложения без доступного адреса показываются как недоступные. Контент, скрытый веб-версией или доступный только через временный `blob:`, эта версия не восстанавливает.

Между сообщениями разных дней показываются разделители `ДД.ММ.ГГГГ`; если день определить нельзя — «Дата неизвестна». Предыдущие архивы с пустыми датами требуют нового экспорта: одни только часы не позволяют восстановить день.

## Важные ограничения

- Экспорт использует отображаемый интерфейс MAX. Перед экспортом расширение делает вкладку MAX активной, чтобы фоновые ограничения таймеров не замедляли прокрутку. После сохранения возвращается к странице отчёта. До окончания оставьте MAX активным; не закрывайте и не обновляйте его. Во время работы интерфейс может переключаться между чатами и помечать сообщения прочитанными.
- При экспорте выбранных чатов расширение нажимает строку чата и проверяет заголовок, маршрут и выделение в доступном списке. В узком окне MAX убирает список из DOM после открытия переписки; тогда проверка использует заголовок и маршрут. Название берётся отдельно от подписи о числе участников в сети. Изменение предпросмотра сообщения или перерисовка строки не прерывают экспорт. Если пользователь переключил чат во время чтения, экспорт завершается ошибкой без сохранения сообщений другой переписки.
- «Все найденные чаты» относится к **текущей папке** веб-версии. Если в узком окне открыт чат и список убран из DOM, поиск и переход к следующему чату сначала нажимают штатную кнопку возврата MAX. После поиска исходный чат открывается снова, чтобы режим «Открытый чат» оставался доступен. Если его нельзя однозначно найти по названию, расширение попросит открыть его вручную. Скрытый список не считается пустым: при невозможности возврата появится сообщение о недоступном списке. Для других папок, скрытых и архивных переписок переключите папку в MAX и повторите поиск. Полнота списка отражается в `discoveryComplete` внутри `report.json`.
- Если MAX меняет разметку или не показывает сообщение, вложение, автора либо точную дату в DOM, расширение не может восстановить эти данные. История загружается прокруткой, включая панели с отрицательным `scrollTop`; возможные разрывы и достижение лимитов отмечаются в `report.json`. Поле `complete` означает, что прокрутка открыла дополнительные сообщения и достигла края без обнаруженного разрыва, а не независимое подтверждение серверного числа сообщений. Если прокрутка не сдвигается или не открывает новые сообщения, отчёт содержит `scroll_stalled` либо `history_not_expanded` и `complete: false`.
- При объединении соседних участков истории расширение сверяет порядок сообщений. Повторно показанный участок не добавляется в архив ещё раз; участок без подтверждённого пересечения отмечается как разрыв и не выдаётся за дополнительные сообщения.
- Перед чтением истории расширение ждёт появления прокрутки до 3 секунд. Если MAX ещё не подготовил длинный чат, в отчёте будет `scroll_container_not_found` и `complete: false`; такой результат нельзя считать полной историей.
- При чтении расширение сразу переходит к верхнему краю смонтированной истории и посылает `scroll`. Искусственные события `wheel` больше не отправляются. Для обратных панелей сохранена поддержка отрицательного `scrollTop`. На каждом шаге оно заново находит панель, чтобы не прокручивать элемент, заменённый MAX при перерисовке. Пока MAX показывает индикатор загрузки, неподвижный список не считается концом истории. Программные события могут обрабатываться иначе, чем действия пользователя; полноту нужно проверять по результату живого экспорта.
- Если после открытия чата первый проход не добавил ни одного старого сообщения, расширение один раз возвращается к последним сообщениям и повторяет проход перед обработкой вложений. Это позволяет заново пересечь границу загрузки после инициализации чата. Число повторов записывается в `history.restarts`; если история всё равно не расширилась, результат остаётся частичным.
- Дни берутся из разделителей MAX `.capsuleSeparator` между внешними блоками `.item`, а также из прежней разметки `.dateSeparator`. Фильтр распознаёт ISO-дату, `ДД.ММ.ГГГГ`, русские и английские названия месяцев, «Сегодня»/«Вчера» и `Today`/`Yesterday`. Метка `New messages` не считается датой. Сообщения с нераспознанной датой сохраняются, чтобы не потерять данные; их число указано в `unknownDates`. Для юридически значимого архива сверяйте результат с исходным чатом.
- Когда веб-версия показывает имя отправителя в заголовке сообщения, экспорт сохраняет его отдельно от текста, без подписи роли. Вложенные `.text` внутри заголовка и времени не добавляются в тело сообщения; сообщение только с фотографией не получает часы в качестве текста. Распознанная дата записывается в поле `date` формата `ГГГГ-ММ-ДД` и отображается в HTML, CSV и TXT.
- Название архива берётся из заголовка чата без меняющегося счётчика участников «в сети».
- Фотографии, показанные плитками с встроенной заглушкой, сохраняются как вложения `photo-tile`. При включённом скачивании после чтения истории расширение открывает штатный просмотрщик каждой фотографии и сразу берёт адрес показанного изображения. Кнопка загрузки в просмотрщике не нажимается: ожидание перехвата её ответа могло занимать до 15 секунд на фото и приводить к отдельной загрузке вместо ZIP. В метаданных указывается `quality: viewer` и доступные размеры изображения. Исходное разрешение не гарантировано. После получения адреса просмотрщик закрывается. Не полученные фотографии перечисляются в `skippedMedia`, поле `detail` различает уже открытый просмотрщик, неоткрывшийся просмотрщик, недоступное изображение и сообщение, не найденное повторно.
- При включённом скачивании после чтения истории расширение повторно проходит нужные участки чата, нажимает штатные кнопки **Скачать** у файлов, перехватывает созданный веб-версией адрес загрузки и пытается включить файл в ZIP. Это позволяет получить файлы даже после удаления их строк из DOM при прокрутке. Поле `history.mediaResolution` показывает число сообщений с такими файлами, число не найденных повторно и `failedFiles` — число вложений, оставшихся без адреса. Перед обработкой сообщение и фотография прокручиваются в видимую область; затем список вложений перечитывается, поскольку MAX может заменить заглушку настоящим фото или видео. Сопоставление на этом этапе не зависит от изменившегося списка вложений. Кэш адресов различает DOM-строки, чтобы одинаковые подписи не объединяли разные фотографии. Фото, видео и аудио с прямыми адресами также загружаются. Поддерживаются HTTPS-адреса в домене `max.ru`, его поддоменах, на `i.oneme.ru`, `fd.oneme.ru` и узлах `maxvd…okcdn.ru`; последние адреса обнаружены в пользовательских архивах MAX. Другие адреса и вложения без доступного URL остаются в метаданных. Предел — 25 МБ на файл и 250 МБ на один ZIP. Каждая загрузка ограничена 30 секундами. Пропуски перечислены в `skippedMedia`. Веб-версия может показывать уменьшенную копию изображения, поэтому разрешение сохранённого файла нужно сверять с оригиналом.
- Пользовательская проверка 20 октября 2026 года: режим открытого чата собрал все 140 сообщений, автоматическое открытие выбранного чата остановилось на 30. В живом DOM найдены фотографии-плитки с заглушками; их прямой адрес появляется в штатном просмотрщике. Штатной кнопкой MAX скачана одна настоящая фотография (110715 байт, сигнатура JPEG); это подтверждает доступность файла, но не автоматическую выгрузку всех фото. В версии 0.3.1 добавлены повтор первого прохода и получение фотографий через просмотрщик. Они проверены на регрессионных тестах и синтетическом браузерном макете; последний архив 0.3.1 содержит 30 сообщений и причину `timeout`: за 10 минут выполнено только 13 шагов прокрутки, верх истории не достигнут. Это согласуется с задержками фоновой вкладки; причина не подтверждена отдельным измерением таймеров. Теперь MAX активируется до начала чтения, а после сохранения этап меняется на «Экспорт завершён». Порядок переключения и сохранения проверяется тестом `test/export-run.test.js`; полнота живого экспорта после исправления ещё не подтверждена.

Расширение запрашивает доступ к вкладке MAX, доменам `max.ru`, `oneme.ru` и `okcdn.ru` для файлов, а также к API загрузок браузера для сохранения ZIP. На `okcdn.ru` оно принимает только HTTPS-узлы с именем `maxvd` и цифрами. Оно не считывает токен аккаунта и не вызывает неофициальные серверные методы MAX. Исходный код доступен для проверки до установки.

## Проверка

Версия 0.3.5 исправляет проход по отложенно загружаемым вложениям. Пользовательский результат 0.3.4 подтверждён по локальному отчёту: 141 сообщение, `reason: top`, без разрывов и неизвестных дат; в `media/` один файл, 153 фото без адреса и один тайм-аут видео. Поэтому прежние проверки на одном доступном фото недостаточны для этого чата. В живом MAX обычное нажатие фото открыло HTTPS-изображение 1920×1440; после прокрутки DOM содержит четыре готовых видео вместо одного, обнаруженного архивом. Проходят 50 тестов, включая фото вне экрана и изменение заглушки в видео. Браузерный макет, где фото нельзя открыть вне панели, собрал 90 сообщений и отдельно выполнил лимит 60; адрес фото получен ([снимок](docs/max-035-media-test.png)). Тайм-аут скачивания потока `maxvd…okcdn.ru` остаётся отдельным непроверенным случаем; полный живой экспорт вложений 0.3.5 ещё не подтверждён.

Версия 0.3.4 меняет загрузку истории: переход к краю вместо десятков мелких шагов и короткие паузы через `timer-worker.js`, чтобы не зависеть от фоновых таймеров страницы. Новых разрешений не требуется. При недоступном служебном процессе остаётся резервное ожидание на странице. Тест с полностью остановленными таймерами страницы проходит через настоящий обработчик worker; отдельный тест проверяет ожидание видимого loader MAX. Всего проходит 48 тестов. Последний пользовательский архив 0.3.3 содержит 30 сообщений и `timeout`; в живом MAX переход `Ctrl+Home` увеличил DOM с 31 до 60, затем до 89 и 118 сообщений. Браузерный макет с обновлённой прокруткой прошёл: 90 сообщений и отдельный лимит 60 ([снимок](docs/max-034-browser-test.png)). Позднейшая пользовательская проверка подтвердила чтение 141 сообщения; результат вложений разобран выше. После обновления расширения нужна перезагрузка MAX.

В версии 0.3.3 исправлены даты из английского интерфейса MAX и добавлен просмотр медиа в HTML. Даты и фильтрация покрыты регрессионными тестами на разметке, найденной в живой вкладке. Пример HTML с синтетическими файлами проверен на ширинах 390, 768 и 1280 пикселей, включая воспроизведение видео WebM и аудио WAV, длинное имя документа и неизвестную дату. Физический телефон не использовался. Живой повторный экспорт 0.3.3 ещё не подтверждён.

Версия 0.3.2: исправления активации MAX и ожидания фотографий проверены автоматическими тестами; браузерный макет собрал 90 сообщений и отдельно соблюл лимит 60, сохранив адреса файлов и фото. Снимок результата: [браузерный тест](docs/max-032-browser-test.png). Полный живой экспорт этой версии в MAX пока не подтверждён. После обновления расширения перезагрузите вкладку MAX, чтобы заменить уже внедрённый `content.js`.

```powershell
npm test
node --check content.js
node --check export.js
node --check download-bridge.js
```

Автоматический браузерный макет использует синтетический чат, не подключаясь к аккаунту MAX. Запуск из `D:\DEV\MaxExport`:

```powershell
Set-Location D:\DEV\MaxExport
npm run test:browser
```

Откройте `http://127.0.0.1:8767/test/stream-fixture.html`. Проверка запускается при загрузке страницы: сначала чат закрыт, затем открывается и загружается порциями по 30 сообщений. Проверяются вся история из 90 сообщений и лимит 60, порядок сообщений, имена отдельно от тела, даты из внешних `.item`/`.capsuleSeparator` и отбор ровно 30 сообщений за 19 октября, начало обработки вложений только после чтения истории, адреса файлов через настоящий `download-bridge.js`, получение фотографии из просмотрщика без нажатия его кнопки скачивания, закрытие просмотрщика и создание ZIP через `format.js`/`zip.js`. Итог — `status: passed` в блоке результата. Чтобы повторить после правки, обновите страницу. Остановка сервера — `Ctrl+C` в терминале; повторный запуск той же командой проверен.

Пример готового HTML из того же генератора: `http://127.0.0.1:8767/test/archive-preview.html`. Команда запуска из `D:\DEV\MaxExport` — `npm run test:browser`; остановка — `Ctrl+C`. Файлы в примере синтетические, их готовые версии хранятся в `fixtures/`, FFmpeg для просмотра не нужен. Снимки: [телефон](docs/max-033-html-mobile.png), [планшет](docs/max-033-html-768.png), [десктоп](docs/max-033-html-1280.png).

Сервер слушает только `127.0.0.1:8767` и отдаёт перечисленные тестовые файлы, без доступа к остальному каталогу. Автотест не проверяет API установки расширения, страницу `export.html`, сетевое скачивание реальных файлов и серверную полноту MAX. Проверка макета в Chromium прошла на размерах 390, 768 и 1024 пикселя; это эмуляция размера окна, не физический телефон.

Для контрольного экспорта создайте тестовый чат с разными типами сообщений, экспортируйте его в HTML + JSON, сравните число и порядок сообщений с MAX, проверьте `report.json` и откройте HTML из распакованного ZIP. Затем проверьте экспорт нескольких чатов и отдельной папки.

Скачанные пакеты аналогов и разбор их реализации: [исходники двух расширений](docs/research-exporter-source-review.md). Пакеты лежат локально в `.research/`, исключены из Git и не устанавливались.

Исследование существующих решений и официальных ограничений: [docs/research-existing.md](docs/research-existing.md).
