## Что требует отдельной проверки

- `manifest.json`: `tabs`, `storage`, `downloads`; wildcard MAX/CDN; API GitHub, raw GitHub и приёмник обращений. Это поверхность для ревью, не доказанная уязвимость. Перечисленные пути host permissions не следует считать серверным разграничением доступа.
- `download-bridge.js` работает в MAIN world и обменивается `postMessage` со страницей; `content.js` проверяет source/origin/marker/nonce. Скрипты того же окна могут наблюдать обмен; нужно проверить фактические возможности злоупотребления и URL/redirect-путь, прежде чем формулировать finding.
- Поиск `incognito|inIncognito|setAccessLevel` в JS вне `test/` и `fixtures/` совпадений не дал; в манифесте явного запрета incognito нет. Реальное поведение при ручном разрешении работы в приватном окне не проверено. Это пробел проверки, не подтверждённая утечка.
- `checkpoint.js` использует IndexedDB `max-archive-checkpoints`; `reporting.js` — `chrome.storage.local`. Проверить жизненный цикл копий и доступ из разных контекстов. Отдельного privacy/security документа поиск по именам файлов не обнаружил; README уже описывает отправку обращений и ограничения обезличивания, поэтому описание данных следует дополнить, а не создавать противоречащий ему текст.
- `docs/development.md` прямо отмечает отсутствие отдельного прогона реального MAX для 0.3.20 и более ранних проверенных макетов. Исторические визуальные/серверные результаты в документации не являются новой проверкой в этой сверке.

Сканеры секретов/SAST, браузерная установка, реальный экспорт, визуальная QA, потребление памяти и сетевой захват в этой работе не выполнялись. Подтверждённых новых эксплуатируемых уязвимостей эта ограниченная сверка не устанавливает. Поведение расширения не менялось.
