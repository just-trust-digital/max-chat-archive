# Разработка

## Известные проблемы

Краткий публичный список хранится в `KNOWN_ISSUES.md` и `known-issues.json`; GitHub Issues хранит подтверждённый статус каждой проблемы. Страница расширения `known-issues.html` загружает JSON из публичного репозитория и использует включённую в пакет копию при недоступной сети. Для списка в манифесте указан `raw.githubusercontent.com/just-trust-digital/max-chat-archive/*`. Автоматизация Codex «MAX Архив — известные проблемы» проверяет список по понедельникам в 10:00 по местному времени, сверяет задачи проекта MAX Архив в Multica через CLI и публикует изменения только при подтверждённом статусе. Исходные отчёты и личные данные туда не копируются.

Расширение Manifest V3 на JavaScript, HTML и CSS, без сборщика и внешних зависимостей во время работы. Версия задаётся в `manifest.json` и `package.json`.

## GlitchTip

В общем GlitchTip на `https://pult.justtrust.digital/bugs/` есть отдельный проект `MaxExport`. Форма посылает отчёт только после просмотра и согласия на `https://pult.justtrust.digital/bugs/report/v1`. Отдельный приёмник сохраняет исходный отчёт с уникальным `(product, report_id)` в закрытом SQLite inbox; подтверждённый пользователем текст пересылает в закрытую карточку GlitchTip: кратко в заголовок и полностью в контекст события. Контакт остаётся только в приёмнике. Ключ проекта хранится только на `koara-live`, в пакет не входит. Отправка ограничена 20 локальными записями за 14 дней, шестью попытками с backoff и лимитами приёмника. Отказ или закрытие вкладки MAX не считается крашем. Подробности сервера и проверок — в [AgentOps runbook](https://github.com/just-trust-digital/AgentOps/blob/codex/glitchtip-pult-memory/services/glitchtip/README.md) (закрытый репозиторий).

## Проверки

Интеграционная проверка безопасности `scripts/audit-browser.cjs` запускает отдельный Chromium с включённой песочницей и новым синтетическим профилем. Проверяет доступ к хранилищу из настоящего content-script контекста, поиск/активацию MAX без `tabs`, запрет перенаправлений в настоящем загрузчике, прямое скачивание и удаление IndexedDB-копии вместе с файлами. Все начальные внешние запросы перехватываются; адрес тестового перенаправления — закрытый локальный порт. Реальный аккаунт не используется.

Проверенный PowerShell-запуск из корня репозитория с runtime Local Codex и установленным тестовым Chromium:

```powershell
$env:NODE_PATH = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules'
$env:MAX_AUDIT_BROWSER = (Get-ChildItem (Join-Path $env:LOCALAPPDATA 'ms-playwright\chromium-*\chrome-win64\chrome.exe') | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
node scripts/audit-browser.cjs
```

Точка входа — синтетическая `https://web.max.ru/`, далее локальная страница установленного расширения. Остановка — `Ctrl+C`, при нормальном завершении браузер закрывается сам. Для проверки распакованного установочного ZIP задайте `$env:MAX_AUDIT_EXTENSION` абсолютным путём к его `MaxExport`; после проверки снимите переменную через `Remove-Item Env:MAX_AUDIT_EXTENSION`. Результат — `output/security-audit/browser-after.json`; профили в этой же папке содержат только синтетические данные. Это техническая интеграционная проверка, не новый прогон реального аккаунта и не визуальная приёмка интерфейса.

Загрузчик вложений отклоняет HTTP, URL с логином/паролем и нестандартным портом до запроса. Автоматические HTTP-перенаправления запрещены (`redirect: error`), referrer не отправляется. Если файловый сервер MAX отвечает перенаправлением, вложение попадает в пропущенные в `report.json`; для добавления такого маршрута нужен отдельный проверенный способ, а не снятие ограничения доменов. Проверка `test/media-download.test.js` использует локальный HTTP-сервер и подтверждает отсутствие запроса к адресу назначения 302.

После проверки 25 октября локальное `chrome.storage.local` ограничено уровнем `TRUSTED_CONTEXTS` при старте service worker: content script MAX не читает настройки и очередь обращений. Инкогнито явно запрещён манифестом. Разрешение `tabs` удалено: URL MAX доступен по уже выданному host permission, для создания/активации вкладок это разрешение не требуется. Wildcard MAX/CDN сохранён из-за меняющихся узлов файлов; загрузчик дополнительно ограничивает допустимые хосты. [Описание данных для пользователя](../PRIVACY.md) входит в установочный пакет.

Перед выпуском используйте [профиль готовности расширения](release-readiness.md): приоритеты для реального экспорта, безопасности и приватности. [Доказательства сверки 0.3.20](release-readiness-evidence.md) отделяют пройденные тесты от ещё не выполненных проверок.

## Пакет для тестировщиков

На Windows нужны Python, `reportlab`, `pypdf` и системные шрифты Arial. Для установки зависимостей в свою среду:

```powershell
python -m pip install -r scripts/requirements-release.txt
python scripts/package-test-release.py
```

Результаты:

- `output/max-archive-<версия>-test.zip`: устанавливаемая папка `MaxExport` и `START-HERE.pdf`.
- `output/pdf/max-archive-quick-start.pdf`: отдельная инструкция на одной странице.
- `output/max-archive-<версия>-test.zip.sha256`: контрольная сумма ZIP.

Скрипт использует явный список `FILES`, включая лицензию, проверяет целостность ZIP и совпадение с исходниками. Профили, переписки, тесты и Git в пакет не входят. После изменения зависимостей расширения обновите список `FILES`. PDF нужно отрендерить и осмотреть перед публикацией; проверка одной страницы и извлечённого текста в скрипте не заменяет визуальную проверку.

## GitHub Actions и релизы

`CI` запускается на push в любую ветку, pull request и вручную. На Ubuntu с Node.js 22 выполняются `npm run check` (совпадение версий и синтаксис всех отслеживаемых Git файлов JavaScript, включая CJS/MJS) и `npm test`. Устанавливать npm-зависимости не требуется. Затем Windows с Python 3.12 и системным Arial создаёт пакет существующим упаковщиком: проверяются целостность ZIP, точный состав по `FILES`, совпадение байтов с исходниками, одна страница PDF и обязательный текст. Зависимости Python закреплены в `scripts/requirements-release.txt`: ReportLab 4.4.9, pypdf 6.21.2, Pillow 13.0.0 и charset-normalizer 3.5.2. pypdf заменила 6.10.0 после проверки OSV 25 октября; четыре текущие версии не имеют известных OSV advisories на момент проверки. Это зависимости упаковщика, в расширение они не входят. После обновлений повторно проверяйте состав окружения, OSV и сборку PDF/ZIP.

Артефакт `tester-bundle` в завершённом запуске Actions содержит установочный ZIP, SHA256 и отдельный PDF; срок хранения — 14 дней. Это результат автоматических проверок, а не подтверждение визуального качества или полноты реального экспорта.

Для следующего выпуска обновите обе версии и подготовьте `docs/releases/v<версия>.md` с проверенными изменениями для пользователя, порядком обновления и известными ограничениями. После коммита отправьте тег, например (подставьте новую версию; существующие теги не перемещать):

```powershell
# Выполните из корня репозитория
$version = (Get-Content -Raw -Encoding UTF8 manifest.json | ConvertFrom-Json).version
git tag -a "v$version" -m "MAX Архив $version"
git push origin "v$version"
```

`Draft release` на push тега `v*` повторно вызывает весь CI для коммита тега и требует точного совпадения `v<версия>`. После успешных проверок он берёт пакет из того же запуска, сверяет SHA256 и создаёт **неопубликованный тестовый Release** с ZIP, SHA256, PDF и текстом из `docs/releases/v<версия>.md`. Секреты реального аккаунта MAX не используются. Права записи есть только у задания создания черновика, а не у CI для pull request.

Перед публикацией скачайте пакет черновика, отрендерите и осмотрите PDF, установите расширение и выполните ручную проверку из раздела выше. Проверьте release notes и только затем публикуйте Release в GitHub. Автопубликации нет. Новый workflow не запускается задним числом для уже выпущенных тегов. Повторный запуск не заменяет существующий Release или черновик; при частичном сбое проверьте его вложения и завершите подготовку вручную. GitHub Packages для расширения не используется.

## Проверка обновлений

`updates.js` монтирует раздел details перед футером в меню и настройках. При каждом открытии GET публичного API `/repos/just-trust-digital/max-chat-archive/releases?per_page=30` ограничен 8 секундами, без credentials. Берётся максимальная числовая версия из последних 30 релизов, включая prerelease (проект распространяет тестовые версии); draft, некорректные теги, отсутствующие/незагруженные ZIP и чужие URL исключаются. Версии сравниваются по компонентам, а не строкой. Удалённый код не исполняется. Метаданные не кешируются. Возможен GitHub rate limit; при ошибке панель предлагает повторить проверку.

Загрузка через Downloads API всегда использует относительный путь `MAX-Archive-updates/max-archive-<версия>-test.zip`, `conflictAction: uniquify`, `saveAs: false`. Это подпапка текущих Загрузок, а не каталог установки. Панель подтверждает только запуск скачивания, не его завершение и не установку. Подробнее: [Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads), [GitHub releases](https://docs.github.com/en/rest/releases/releases). Отдельные проверки: `node --test test/updates.test.js`.

Макеты обновлений: `/test/popup-preview.html?theme=dark&update=available` и `/test/export-visibility.html?tab=7&fixture=recovery&update=available`. Параметр `update=current`, `offline` или `download-error` переключает состояние. Реальные GitHub и Downloads в этих макетах заменены синтетическими данными.

Если 8767 занят, проверенный запуск на 8768:

```powershell
# Выполните из корня репозитория
$env:MAX_ARCHIVE_FIXTURE_PORT='8768'
npm run test:browser
```

Откройте http://127.0.0.1:8768/test/popup-preview.html?utm_source=jtd_dev . Остановка — `Ctrl+C`. Для возврата к порту по умолчанию: `Remove-Item Env:MAX_ARCHIVE_FIXTURE_PORT -ErrorAction SilentlyContinue`. Сайт не публикуется.

Проверка 23 октября 2026: 4 теста обновлений и весь набор из 103 тестов проходят. Тестовая среда без `window` также проходит после добавления защиты для глобальных обработчиков ошибок в `export.js`.

Настройки визуально проверены в браузере через iframe 390/768/1280 px, светлая/тёмная темы; [снимки и геометрия](update-preview/geometry.json). Ширина документа совпадает с шириной iframe, кнопка находится внутри панели. Меню проверено в состояниях available/current/offline/download-error и с длинной инструкцией после имитации запуска загрузки. Это синтетические браузерные макеты, не физический телефон и не установленное расширение. Реальная запись ZIP через Chrome Downloads и экспорт аккаунта MAX в этой задаче не проверялись. Реальные публичные метаданные релизов GitHub получены через `gh api`: последние 0.3.12 и 0.3.11 имеют `prerelease: true` и ожидаемые ZIP.

Артефакты из `output/` исключены из Git; для распространения прикрепляйте ZIP, PDF и SHA-256 к GitHub Release. При обновлении релиза обновите версию в манифесте и `package.json`, ссылки и номер версии в README, затем пересоберите пакет.

## Вывод в папку (0.3.10)

`directory.js` реализует тот же интерфейс `add`, что и ZIP, и последовательную очередь скачиваний с `flush`. `export.js` передаёт запись в `saveBlob` с `conflictAction: overwrite`: это нужно для обновления собственного `index.html` и отчёта внутри нового каталога с уникальным кодом. Существующие каталоги не выбираются. Нельзя передавать в этот класс произвольный пользовательский корневой путь. Файлы скачиваются относительно Downloads; абсолютные пути, обратные переходы и недопустимые компоненты отвергаются. Описание Chrome: https://developer.chrome.com/docs/extensions/reference/api/downloads .

Выбор произвольной папки через `showDirectoryPicker` не используется: доступность и поведение в расширениях отличаются от обычной страницы. Проверены очередь, вложенные пути, сохранение двух чатов без конструктора ZIP, остановка при ошибке диска и при прерывании скачивания. Браузерный макет: http://127.0.0.1:8767/test/directory-fixture.html?utm_source=jtd_dev ; он проверяет формирование отдельных файлов и байты в памяти браузера, а не реальную запись в Downloads. Для живой проверки загрузите текущую версию расширения, обновите MAX, выберите папку в настройках и сверьте реальные файлы на диске. Такой прогон на аккаунте этой версии пока не подтверждён.

Рендеры нового выбора сохранения проверены на ширинах 390, 768 и 1280, в светлой и тёмной темах. Разбиение ZIP отключено в режиме папки, кнопка называется «Сохранить в папку»; переполнения по горизонтали нет. Снимки: [768](folder-settings-light-768.png), [390](folder-settings-dark-390.png), [макет файлов без ZIP](folder-output-proof.png). Скрипт макетов увеличивает высоту iframe, чтобы новая настройка не обрезала нижние элементы.

## Настраиваемые лимиты

`maxFileMB` (25 по умолчанию, 1–2000) и `maxArchiveMB` (250, 1–4000) сохраняются с остальными настройками. `ArchiveBudget` оборачивает ZIP/DirectoryArchive, учитывает UTF-8 и заголовки ZIP, для папки — замену файлов. Файл проверяется по Content-Length и реально прочитанным байтам; бюджет применяется к папке, общему ZIP и отдельно к каждому ZIP. Blob голосового получает тот же лимит в download-bridge; исходная запись не проигрывается. При нехватке места для текстовых файлов возникает ARCHIVE_LIMIT; контрольные точки сохранены. Восстановление старых копий сохраняет прежнее поведение.

## Скриншоты в обращениях

Форма принимает до двух выбранных пользователем PNG/JPEG/WebP. Canvas пересохраняет их в WebP, ограничивает длинную сторону 1280 px и каждый снимок 160 КиБ; исходное имя файла и EXIF не отправляются. Превью показывает именно подготовленные байты. Перед отправкой нужны согласие на обращение и отдельное согласие на снимки. Без выбора файлов расширение не создаёт изображения и не читает вкладку MAX.

В `reporting.js` та же пара снимков и ID сохраняется при сетевой ошибке и повторной отправке; общий локальный бюджет вложений — 3 МиБ. При лимите 160 КиБ на снимок фактический максимум двух вложений меньше этого бюджета. После подтверждённого приёма байты удаляются из очереди браузера. HTTPS-приёмник ограничивает тело 512 КиБ и хранит WebP в приватной таблице `report_images` с общим лимитом 256 МиБ. В GlitchTip попадают текст, количество и адреса снимков, но не их байты: GlitchTip 6.2.6 игнорирует обычные вложения в envelope и показывает адрес как текст без клика и превью. Его можно скопировать в браузер. По адресу приёмник отдаёт WebP только при действующей сессии с доступом к проекту MaxExport; без неё отвечает 403. Оператор также может получить копию через `intake.py export-image`. Сведения о развёртывании — в [закрытом runbook AgentOps](https://github.com/just-trust-digital/AgentOps/blob/codex/glitchtip-pult-memory/services/glitchtip/README.md).
