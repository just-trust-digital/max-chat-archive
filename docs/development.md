# Разработка

## Известные проблемы

Краткий публичный список хранится в `KNOWN_ISSUES.md` и `known-issues.json`; GitHub Issues хранит подтверждённый статус каждой проблемы. Страница расширения `known-issues.html` загружает JSON из публичного репозитория и использует включённую в пакет копию при недоступной сети. Для списка в манифесте указан `raw.githubusercontent.com/just-trust-digital/max-chat-archive/*`. Автоматизация Codex «MAX Архив — известные проблемы» проверяет список по понедельникам в 10:00 по местному времени, сверяет задачи проекта MAX Архив в Multica через CLI и публикует изменения только при подтверждённом статусе. Исходные отчёты и личные данные туда не копируются.

Расширение Manifest V3 на JavaScript, HTML и CSS, без сборщика и внешних зависимостей во время работы. Версия задаётся в `manifest.json` и `package.json`.

## GlitchTip

В общем GlitchTip на `https://pult.justtrust.digital/bugs/` есть отдельный проект `MaxExport`. Форма посылает отчёт только после просмотра и согласия на `https://pult.justtrust.digital/bugs/report/v1`. Отдельный приёмник сохраняет исходный отчёт с уникальным `(product, report_id)` в закрытом SQLite inbox; подтверждённый пользователем текст пересылает в закрытую карточку GlitchTip: кратко в заголовок и полностью в контекст события. Контакт остаётся только в приёмнике. Ключ проекта хранится только на `koara-live`, в пакет не входит. Отправка ограничена 20 локальными записями за 14 дней, шестью попытками с backoff и лимитами приёмника. Отказ или закрытие вкладки MAX не считается крашем. Подробности сервера и проверок — в [AgentOps runbook](https://github.com/just-trust-digital/AgentOps/blob/codex/glitchtip-pult-memory/services/glitchtip/README.md) (закрытый репозиторий).

## Проверка обновлений

`updates.js` монтирует верхнюю панель в меню и настройках. При каждом открытии GET публичного API `/repos/just-trust-digital/max-chat-archive/releases?per_page=30` ограничен 8 секундами, без credentials. Берётся максимальная числовая версия из последних 30 релизов, включая prerelease (проект распространяет тестовые версии); draft, некорректные теги, отсутствующие/незагруженные ZIP и чужие URL исключаются. Версии сравниваются по компонентам, а не строкой. Удалённый код не исполняется. Метаданные не кешируются. Возможен GitHub rate limit; при ошибке панель предлагает повторить проверку.

Загрузка через Downloads API всегда использует относительный путь `MAX-Archive-updates/max-archive-<версия>-test.zip`, `conflictAction: uniquify`, `saveAs: false`. Это подпапка текущих Загрузок, а не каталог установки. Панель подтверждает только запуск скачивания, не его завершение и не установку. Подробнее: [Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads), [GitHub releases](https://docs.github.com/en/rest/releases/releases). Отдельные проверки: `node --test test/updates.test.js`.

Макеты обновлений: `/test/popup-preview.html?theme=dark&update=available` и `/test/export-visibility.html?tab=7&fixture=recovery&update=available`. Параметр `update=current`, `offline` или `download-error` переключает состояние. Реальные GitHub и Downloads в этих макетах заменены синтетическими данными.

Если 8767 занят, проверенный запуск на 8768:

```powershell
Set-Location D:\DEV\MaxExport
$env:MAX_ARCHIVE_FIXTURE_PORT='8768'
npm run test:browser
```

Откройте http://127.0.0.1:8768/test/popup-preview.html . Остановка — `Ctrl+C`. Для возврата к порту по умолчанию: `Remove-Item Env:MAX_ARCHIVE_FIXTURE_PORT -ErrorAction SilentlyContinue`. Сайт не публикуется.

Проверка 23 октября 2026: 4 теста обновлений и весь набор из 103 тестов проходят. Тестовая среда без `window` также проходит после добавления защиты для глобальных обработчиков ошибок в `export.js`.

Настройки визуально проверены в браузере через iframe 390/768/1280 px, светлая/тёмная темы; [снимки и геометрия](update-preview/geometry.json). Ширина документа совпадает с шириной iframe, кнопка находится внутри панели. Меню проверено в состояниях available/current/offline/download-error и с длинной инструкцией после имитации запуска загрузки. Это синтетические браузерные макеты, не физический телефон и не установленное расширение. Реальная запись ZIP через Chrome Downloads и экспорт аккаунта MAX в этой задаче не проверялись. Реальные публичные метаданные релизов GitHub получены через `gh api`: последние 0.3.12 и 0.3.11 имеют `prerelease: true` и ожидаемые ZIP.

Артефакты из `output/` исключены из Git; для распространения прикрепляйте ZIP, PDF и SHA-256 к GitHub Release. При обновлении релиза обновите версию в манифесте и `package.json`, ссылки и номер версии в README, затем пересоберите пакет.

## Вывод в папку (0.3.10)

`directory.js` реализует тот же интерфейс `add`, что и ZIP, и последовательную очередь скачиваний с `flush`. `export.js` передаёт запись в `saveBlob` с `conflictAction: overwrite`: это нужно для обновления собственного `index.html` и отчёта внутри нового каталога с уникальным кодом. Существующие каталоги не выбираются. Нельзя передавать в этот класс произвольный пользовательский корневой путь. Файлы скачиваются относительно Downloads; абсолютные пути, обратные переходы и недопустимые компоненты отвергаются. Описание Chrome: https://developer.chrome.com/docs/extensions/reference/api/downloads .

Выбор произвольной папки через `showDirectoryPicker` не используется: доступность и поведение в расширениях отличаются от обычной страницы. Проверены очередь, вложенные пути, сохранение двух чатов без конструктора ZIP, остановка при ошибке диска и при прерывании скачивания. Браузерный макет: http://127.0.0.1:8767/test/directory-fixture.html ; он проверяет формирование отдельных файлов и байты в памяти браузера, а не реальную запись в Downloads. Для живой проверки загрузите текущую версию расширения, обновите MAX, выберите папку в настройках и сверьте реальные файлы на диске. Такой прогон на аккаунте этой версии пока не подтверждён.

Рендеры нового выбора сохранения проверены на ширинах 390, 768 и 1280, в светлой и тёмной темах. Разбиение ZIP отключено в режиме папки, кнопка называется «Сохранить в папку»; переполнения по горизонтали нет. Снимки: [768](folder-settings-light-768.png), [390](folder-settings-dark-390.png), [макет файлов без ZIP](folder-output-proof.png). Скрипт макетов увеличивает высоту iframe, чтобы новая настройка не обрезала нижние элементы.

## Настраиваемые лимиты

`maxFileMB` (25 по умолчанию, 1–2000) и `maxArchiveMB` (250, 1–4000) сохраняются с остальными настройками. `ArchiveBudget` оборачивает ZIP/DirectoryArchive, учитывает UTF-8 и заголовки ZIP, для папки — замену файлов. Файл проверяется по Content-Length и реально прочитанным байтам; бюджет применяется к папке, общему ZIP и отдельно к каждому ZIP. Blob голосового получает тот же лимит в download-bridge; исходная запись не проигрывается. При нехватке места для текстовых файлов возникает ARCHIVE_LIMIT; контрольные точки сохранены. Восстановление старых копий сохраняет прежнее поведение.


## Русский календарь и подписи

`calendar.js` управляет собственным dialog: русский список месяцев, понедельник в первом столбце, диапазон 1900–2100. Исходные SVG JTD сохранены, подпись удалена по прямому указанию владельца.
