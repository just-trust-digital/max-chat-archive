# Разработка

## Известные проблемы

Краткий публичный список хранится в `KNOWN_ISSUES.md` и `known-issues.json`; GitHub Issues хранит подтверждённый статус каждой проблемы. Страница расширения `known-issues.html` загружает JSON из публичного репозитория и использует включённую в пакет копию при недоступной сети. Для этого в манифесте указан только `raw.githubusercontent.com/just-trust-digital/max-chat-archive/*`. Автоматизация Codex «MAX Архив — известные проблемы» проверяет список по понедельникам в 10:00 по местному времени, сверяет задачи проекта MAX Архив в Multica через CLI и публикует изменения только при подтверждённом статусе. Исходные отчёты и личные данные туда не копируются.

Расширение Manifest V3 на JavaScript, HTML и CSS, без сборщика и внешних зависимостей во время работы. Версия задаётся в `manifest.json` и `package.json`.

Использованы синтетические данные и iframe, не физический телефон. Снимки: [узкая тёмная тема](max-040-period-dark-390.png), [период и история](max-040-period-light-768.png). Четыре теста `test/download-bridge.test.js` проходят; они проверяют перехват голосовых без вызова настоящего `play()`, но не доказывают отсутствие любого воспроизведения в живом MAX.

## Пакет для тестировщиков

На Windows нужны Python, `reportlab`, `pypdf` и системные шрифты Arial. Для установки зависимостей в свою среду:

```powershell
python -m pip install reportlab pypdf
python scripts/package-test-release.py
```

На компьютере владельца проверена готовая среда Codex:

```powershell
Set-Location D:\DEV\MaxExport
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" scripts/package-test-release.py
```

Результаты:

- `output/max-archive-<версия>-test.zip`: устанавливаемая папка `MaxExport` и `START-HERE.pdf`.
- `output/pdf/max-archive-quick-start.pdf`: отдельная инструкция на одной странице.
- `output/max-archive-<версия>-test.zip.sha256`: контрольная сумма ZIP.

Скрипт использует явный список из 22 файлов, включая лицензию, проверяет целостность ZIP и совпадение с исходниками. Профили, переписки, тесты и Git в пакет не входят. После изменения зависимостей расширения обновите список `FILES`. PDF нужно отрендерить и осмотреть перед публикацией; проверка одной страницы и извлечённого текста в скрипте не заменяет визуальную проверку.

Артефакты из `output/` исключены из Git; для распространения прикрепляйте ZIP, PDF и SHA-256 к GitHub Release. При обновлении релиза обновите версию в манифесте и `package.json`, ссылки и номер версии в README, затем пересоберите пакет.

## Вывод в папку (0.3.10)

`directory.js` реализует тот же интерфейс `add`, что и ZIP, и последовательную очередь скачиваний с `flush`. `export.js` передаёт запись в `saveBlob` с `conflictAction: overwrite`: это нужно для обновления собственного `index.html` и отчёта внутри нового каталога с уникальным кодом. Существующие каталоги не выбираются. Нельзя передавать в этот класс произвольный пользовательский корневой путь. Файлы скачиваются относительно Downloads; абсолютные пути, обратные переходы и недопустимые компоненты отвергаются. Описание Chrome: https://developer.chrome.com/docs/extensions/reference/api/downloads .

Выбор произвольной папки через `showDirectoryPicker` не используется: доступность и поведение в расширениях отличаются от обычной страницы. Проверены очередь, вложенные пути, сохранение двух чатов без конструктора ZIP, остановка при ошибке диска и при прерывании скачивания. Браузерный макет: http://127.0.0.1:8767/test/directory-fixture.html ; он проверяет формирование отдельных файлов и байты в памяти браузера, а не реальную запись в Downloads. Для живой проверки загрузите текущую версию расширения, обновите MAX, выберите папку в настройках и сверьте реальные файлы на диске. Такой прогон на аккаунте этой версии пока не подтверждён.

Рендеры нового выбора сохранения проверены на ширинах 390, 768 и 1280, в светлой и тёмной темах. Разбиение ZIP отключено в режиме папки, кнопка называется «Сохранить в папку»; переполнения по горизонтали нет. Снимки: [768](folder-settings-light-768.png), [390](folder-settings-dark-390.png), [макет файлов без ZIP](folder-output-proof.png). Скрипт макетов увеличивает высоту iframe, чтобы новая настройка не обрезала нижние элементы.

## Настраиваемые лимиты

`maxFileMB` (25 по умолчанию, 1–2000) и `maxArchiveMB` (250, 1–4000) сохраняются с остальными настройками. `ArchiveBudget` оборачивает ZIP/DirectoryArchive, учитывает UTF-8 и заголовки ZIP, для папки — замену файлов. Файл проверяется по Content-Length и реально прочитанным байтам; бюджет применяется к папке, общему ZIP и отдельно к каждому ZIP. Blob голосового получает тот же лимит в download-bridge; исходная запись не проигрывается. При нехватке места для текстовых файлов возникает ARCHIVE_LIMIT; контрольные точки сохранены. Восстановление старых копий сохраняет прежнее поведение.


## Русский календарь и подписи

`calendar.js` управляет собственным dialog: русский список месяцев, понедельник в первом столбце, диапазон 1900–2100. Видимые кнопки показывают ДД.ММ.ГГГГ, скрытые from/to сохраняют ISO для совместимости фильтров. При восстановлении настроек вызывается ArchiveCalendar.refresh. Навигация дней — стрелки, Home/End, PageUp/PageDown; Escape и кнопка закрытия возвращают фокус к полю. Обязательный текст не отключается, подсказка доступна также с клавиатуры. Исходные SVG JTD сохранены, подпись удалена по прямому указанию владельца.

Проверка уточнений 0.3.12: [снимки и измерения](ui-0312/README.md). Новый календарь подключён перед export.js и включён в установочный ZIP. Прямой макет `/test/export-visibility.html?tab=7&fixture=recovery&theme=light&chats=populated` удобнее для проверки dialog в реальном viewport; ui-layout остаётся вспомогательным сравнением ширин.
