# Перед следующим публичным выпуском MAX Архива

Сверка 25 октября 2026 года для версии 0.3.20, исходный commit `c29c593`. Это предложенный профиль проверки расширения по общему чеклисту из чата «Составить чеклист перед релизом», а не заключение о безопасности. [Доказательства и границы проверки](release-readiness-evidence.md).

**Рекомендация: сначала проверить реальный экспорт и границы доступа к переписке.** Автоматические проверки уже проходят; готовность экспорта реального аккаунта для этой версии пока не подтверждена.

1. [ ] **Установить итоговый ZIP и пройти экспорт на тестовом аккаунте MAX в Chrome и Edge.** Один и несколько чатов, период, фото/видео/голосовые, ZIP и папка; сравнить сообщения и файлы с оригиналом. Прервать экспорт, перезапустить браузер, скачать сохранённое; проверить `report.json`, отсутствие дублей и честное указание пропусков. Обновить установленную предыдущую версию с сохранением настроек и истории. Записать версии браузеров, commit и SHA-256 пакета; переписку в Git не помещать.
2. [ ] **Проверить разрешения и обмен сообщениями со страницей MAX.** Обосновать каждый API и домен в манифесте; проверить возможность сужения `tabs`, `*.max.ru` и `*.okcdn.ru`. Проверить поддельные сообщения, неожиданные схемы URL, перенаправления загрузок и отмену чужого задания. Проверка origin и nonce сама по себе не делает скрипт страницы доверенным.
3. [ ] **Проверить приватность и хранение.** Зафиксировать сетевые обращения при старте, экспорте, проверке обновлений и добровольном отчёте. Переписка и данные аккаунта не должны уходить в поддержку. Проверить удаление локальных копий, ошибки квоты и отдельно приватный режим: если его поддержка не нужна, явно запретить её; иначе исключить отчёты из приватного контекста и проверить хранение. Подготовить отдельное понятное описание обработки данных, включая локальные копии и добровольно отправленные скриншоты.
4. [ ] **Выполнить аудит исходников, истории Git и готового пакета.** Локальный скан секретов с маскированием результатов, анализ JavaScript, проверка HTML/CSV/имён файлов и схем ссылок на вредоносных синтетических данных. Проверить именно распакованный ZIP, его состав, лицензии и SHA-256; чужие профили и экспорты не сканировать. Каждую находку воспроизвести и перепроверить после исправления.
5. [ ] **Завершить приёмку релизного пакета.** Проверить офлайн-ошибки обновлений и поддержки, крупный архив и предел памяти, итоговый HTML без сети, установку по PDF с чистого профиля. После любых изменений интерфейса проверить реальные рендеры, обе темы, клавиатуру и узкое окно. Зафиксировать исключения, инструкцию обновления/возврата и ограничения в release notes. Проверить поддержку и закрытый inbox синтетическим обращением без личных данных.

Минимальный повторяемый запуск из PowerShell:

```powershell
Set-Location 'D:\DEV\MaxExport'
npm run check
npm test
```

25 октября: синтаксис 43 JS-файлов проверен, 110 из 110 тестов прошли. Это не закрывает ручные пункты выше.

Для расширения не нужны автоматически все пункты сайта: 404, sitemap, SEO и рекламные пиксели. При публикации в магазине потребуется отдельная проверка его актуальных требований. Nuclei/Trivy и Android MASTG не являются первым шагом для проверки клиентского экспортёра; сервер приёма обращений проверяется отдельно в разрешённом контуре. Практичный первый набор — скан секретов и анализ JavaScript плюс сценарии выше; сторонние скрипты из закладок без ревью не запускать.
